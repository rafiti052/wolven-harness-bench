# Lessons from the QMD diagnostic campaigns

## Question

What do the four finished QMD diagnostic campaigns show about scoring and instruction placement, and which architecture should a later benchmarks tool in this repo keep?

## Findings

The evidence set is four campaigns under the disposable launcher, each with `retry_from` null. The ten-cell batch is `20261014-184957-e4a78b`. The three stale-only campaigns are the freshness sentence (`20261014-192926-c40668`), the entry-file seed (`20261014-195432-298a0a`), and the skill-description seed (`20261014-200104-afca95`). `manifest.json` still names fixtures `healthy` and `stale`, concurrency 2, a 600-second fixture timeout, an 1800-second preflight deadline, one repetition, and evaluation text "Diagnostic only; no full compliance claim." The shared prompt is "What is the current retry limit for outbound payment delivery, and which document establishes it?" ([manifest.json](file:///Users/rafael/.codex/visualizations/2026/10/14/01a13a56-18a7-7400-bfdc-5c3950477d16/qmd-runtime-matrix/manifest.json))

Healthy success in the launcher README is observed canon search and full retrieval, plus the current answer with attribution. Stale success is detecting the mismatch and refusing to state a current limit, without index repair. ### Architecture to keep

This repo already has a different benchmark: a draft evaluation of four OpenCode workflows, and ADR-001, which runs that smoke from a checkout with Python and uv. The QMD campaigns are a five-runtime diagnostic on native CLIs. The launcher README says a future production evaluator needs a separate approved implementation. These lessons do not revise that draft spec. ([ADR-001](docs/adrs/adr-001-python-uv-smoke-runtime.md), [benchmark-evaluation-spec.md](docs/specs/benchmark-evaluation/benchmark-evaluation-spec.md), [README.md](file:///Users/rafael/.codex/visualizations/2026/10/14/01a13a56-18a7-7400-bfdc-5c3950477d16/qmd-runtime-matrix/README.md))

A campaign has four layers, and a later reader should keep them apart. `oracle.json` holds `old`, `current`, and `note`, drawn by `begin` as three distinct integers from 21 through 997. `state.json` holds `ready` per job. `results.json` holds exit, survivors, and timing. `REPORT.md` holds the behavioral table. `runs/<target>/<fixture>/stdout.jsonl` is the trace. `preflight` builds a workspace per target per fixture, indexes it, and on stale rewrites the payment ADR to `current` at revision 2026-10-02 without reindexing. `fixtures` walks `healthy` then `stale` and launches a job only when `ready` is true and the target qualified, at most two at a time. The three stale-only campaigns left `manifest.json` fixtures as `["healthy", "stale"]` and set the five healthy jobs to `ready: false`. ([matrix.py `begin`](file:///Users/rafael/.codex/visualizations/2026/10/14/01a13a56-18a7-7400-bfdc-5c3950477d16/qmd-runtime-matrix/matrix.py), [matrix.py `preflight`](file:///Users/rafael/.codex/visualizations/2026/10/14/01a13a56-18a7-7400-bfdc-5c3950477d16/qmd-runtime-matrix/matrix.py), [matrix.py `fixtures`](file:///Users/rafael/.codex/visualizations/2026/10/14/01a13a56-18a7-7400-bfdc-5c3950477d16/qmd-runtime-matrix/matrix.py), [freshness state.json](file:///Users/rafael/.codex/visualizations/2026/10/14/01a13a56-18a7-7400-bfdc-5c3950477d16/qmd-runtime-matrix/campaigns/20261014-192926-c40668/state.json))

Each runtime has its own instruction inlet. `workspace` copies `AGENTS.md` to `CLAUDE.md` and `GEMINI.md`, writes `.cursor/rules/harness.mdc` with `alwaysApply: true` plus that body, symlinks `.claude/skills/qmd` at the agents skill, and writes a Cursor allow list that denies `qmd update`, `qmd embed`, and `qmd pull`. The restored `AGENTS.md` says to read the rule, names the skill path, and limits the task to reading and answering. Claude's session-start list can still omit `qmd` while a grep of `SKILL.md` succeeds. The file on disk, the copied entry file, and the runtime's skill list are three surfaces. ([matrix.py `workspace`](file:///Users/rafael/.codex/visualizations/2026/10/14/01a13a56-18a7-7400-bfdc-5c3950477d16/qmd-runtime-matrix/matrix.py), [AGENTS.md](file:///Users/rafael/.codex/visualizations/2026/10/14/01a13a56-18a7-7400-bfdc-5c3950477d16/qmd-runtime-matrix/assets/AGENTS.md), [seed B REPORT.md](file:///Users/rafael/.codex/visualizations/2026/10/14/01a13a56-18a7-7400-bfdc-5c3950477d16/qmd-runtime-matrix/campaigns/20261014-200104-afca95/REPORT.md))

The score for a stale cell, once the later reports had learned the ten-cell ambiguity, is five columns: skill or rule opened, retrieval executed, `qmd get` executed, whether a direct read disagreed with the index, and which number was stated as the current limit. "Neither" is the stale success cell in those tables. Stating the indexed value, or stating the on-disk value without a QMD retrieval, stays in the table as observed behavior. ([freshness REPORT.md](file:///Users/rafael/.codex/visualizations/2026/10/14/01a13a56-18a7-7400-bfdc-5c3950477d16/qmd-runtime-matrix/campaigns/20261014-192926-c40668/REPORT.md))

History stays a hash of bytes. `manifest()` in `repaired-path-smoke.py` sorts relative POSIX paths and, for each file, updates the digest with the path bytes, a NUL, and the raw sha256 digest. The three stale-only reports record campaigns `20261014-170037-4d6132` (187 files, `60ec4dc5fd158bda4db9d2a369c130516007e1ba778e1f59f16d60280cdf02fb`), `20261014-172552-2202fc` (153 files, `82de16fc08a4d3533f40b3f68951576b67e8ed5c0e711fbf70264a209e0ca248`), and `20261014-174811-c18f22` (109 files, `df68fb639b55b3726b4d03b92bdd7c087eb62726842cd6029392f3357971d26e`) as unchanged. ([repaired-path-smoke.py `manifest`](file:///Users/rafael/.codex/visualizations/2026/10/14/01a13a56-18a7-7400-bfdc-5c3950477d16/qmd-runtime-matrix/repaired-path-smoke.py), [seed B REPORT.md](file:///Users/rafael/.codex/visualizations/2026/10/14/01a13a56-18a7-7400-bfdc-5c3950477d16/qmd-runtime-matrix/campaigns/20261014-200104-afca95/REPORT.md))
